# Single-Intent Voice Command Model: Plan

NASA SUITS 2026–27. The astronaut speaks, Whisper turns it into text, and our model picks one of 36 labels (plus a name for 5 of them). The HUD runs the command.

Sources: **MD** = `docs/nasa-suits-mission-description.pdf`. **Siri** = `docs/siri-deep-dive.pdf` (cited by slide title).

---

## 1. Overview

- **Pipeline:** headset mic → link to the MacBook (cable or WiFi) → `faster-whisper` `base.en` → normalizer → MiniLM (intent head + slot head) → reject check → slot resolver → result back to the HUD.
- **Where it runs:** on the MacBook. The HUD connects by cable or by WiFi, which may be weak. Both work (§7.4).
- **Shipped model:** one `all-MiniLM-L6-v2` (22M), fine-tuned and distilled from bigger teachers, exported to ONNX int8. Nothing bigger runs at prediction time.
- **Output:** `{text, selected_intent, confidence, top5, slot?}`. Low confidence → `unhandled`.
- **Guardrail:** the model never produces telemetry values. It only picks a label and a name; the HUD reads values from NASA's telemetry server (MD §2b, §3a).
- **Data:** generated by an agent loop (§3). The agent proposes rows, a blind second model and code decide what is kept, and dev results steer the next round. Every row passes the gates in §4.
- **Done:** the targets in §6.3 are met on the sealed test set, and latency in §7.3 is met on the MacBook.

**Rules**
- One label per utterance. No multi-intent, no domain hierarchy (Siri "Why Classify in Levels": 36 labels fit one softmax).
- Every row is a genuinely different sentence. No templates, no word swaps.
- Every row has a source tag, and results are reported per source (Siri "Supervision Is Data").
- The test set is written and frozen before any generation. The loop steers on dev only.
- Test is sealed: read only at milestones, never mined from (Siri "Data Engine").
- Big models are fine offline (teachers, generators, labellers). Only MiniLM runs live.

## 2. Output and labelling

### 2.1 Output

- `text`: the normalized Whisper transcript.
- `selected_intent`: one of the 36 labels, exact case.
- `confidence`: calibrated probability (§5.4).
- `top5`: five `(label, prob)` pairs.
- `slot`: only on `Get_coordinates`, `Set_navigation_target`, `Add_waypoint`, `Delete_waypoint`, `Complete_task`. Shape: `{span, resolved, candidates[≤3], status}`, where status is `match`, `ask` or `new`.

### 2.2 Labelling rules

The full rules are in [LABELING_GUIDE.md](LABELING_GUIDE.md). It is used to map the found dataset, to prompt the generators, and as the prompt for the LLM labellers. The main rules:

- A request without a qualifier means primary, or total for pressure ("oxygen" → `get_oxy_pri_storage`, "pressure" → `get_suit_pressure_total`). This matches the nominal DCU setup in MD Appendix A. The full table is in the guide.
- A single value → `get_*`. A panel → `open_menu_*`.
- `unhandled`: value read-backs, switch callouts from procedures, out-of-scope requests (camera, spectrometer, comms), cancellations and negated commands.
- `Add_waypoint` keeps the spoken name verbatim, with no HUD confirmation.
- Edge cases (guide §4): "how far is X" → `Get_coordinates`; an unnamed pin or task → empty slot; "body temp" → `get_temperature`; "coolant pressure" → liquid; "what's next" → `open_menu_tasks`; "local" / "UMB" battery and two commands in one sentence → `unhandled`; "drop the X waypoint" is never used.
- **Check:** the blind relabeller agrees with the guide label on ≥ 95% of hand-written dev rows (measured: 96%). Optional: a person reads 100 rows (~20 min) to measure true label accuracy.

## 3. Data

The data comes from an iterative agent loop ([data/DATA_GENERATION.md](data/DATA_GENERATION.md)). The agent (Claude) only proposes rows. Code and a blind second model decide what is kept, and each round's dev results decide what the agent writes next. The code is in `datagen/`.

```
Generate → Filter → Whisper pass → Dedup → Train & evaluate → Target → repeat
```

### 3.1 Row fields

| Field | Meaning |
|---|---|
| `id`, `text`, `label` | the row (always lowercase) |
| `slot_text` | exact substring that is the slot, or null |
| `group`, `split` | aligned-set id and train / dev; a whole group stays in one split |
| `source` | `agent`, `appendix_a`, `tts_roundtrip`, `whisper_silence`, `handwritten_test`, `handwritten_dev` |
| `fam`, `cell`, `kind` | label family, grid cell, and `unhandled` kind (report, chatter, out_of_scope, negation, fragment, noise, callout, jargon_trap) |
| `parent_id`, `round` | source row of a Whisper variant; loop round |

### 3.2 Frozen test, dev and slot pools

- **Test:** written once before the loop, in radio style ([data/style_reference.md](data/style_reference.md)), with slot names used nowhere else. 10 rows per command label and 32 `unhandled` (382 rows). The file is read-only and its hash is in `data/frozen/test.sha256`. Everything derived from it (its Whisper transcripts) also lives in `data/frozen/`. Only `datagen/final_eval.py` opens it, at milestones, and it writes aggregate numbers only, never test row text.
- **Dev (`data/dev_hard.jsonl`, 515 rows):** every loop decision uses it. Written by the agent in radio style and hard by construction ([datagen/dev_hard.py](datagen/dev_hard.py)):
  - Every row is < 0.85 cosine and < 0.6 Jaccard from all same-label train rows (median 0.73; the old dev was 0.82).
  - Slot names come from the dev pool only, mostly multi-word; unnamed pins and tasks included.
  - Late deciding words, disfluency, jargon, contrastive rows ("not the map, the checklist"), and `unhandled` traps: reports, two commands, qualifier-only follow-ups, Whisper noise (16% `unhandled`).
  - ≥ 10 rows per label; same rule checks and two-step blind relabel as train; guide examples and the style reference's Apollo lines are banned.
  - Never chosen by a model's predictions. A separate auditor agent checked 9 guardrails after each batch (`reports/dev_hard_build.json`).
  - Whisper version: `data/gen/dev_hard_asr.jsonl` (317 rows).
  - New train rows must stay < 0.85 cosine from same-label dev rows, so later rounds can't make dev easy again.
- **Old dev** (152 hand-written + 172 from round 0) is saturated at 99.7%; kept only for comparison.
- **Slot names:** three pools that never overlap, not even as substrings ([datagen/slots.json](datagen/slots.json)), built from `data/slot_names.txt` plus generated waypoint names.

### 3.3 Intent cards

- [datagen/cards.json](datagen/cards.json): for each label, its meaning, deciding words, siblings, 3 positives and 3 "looks like it but isn't" rows.
- Card and guide examples are banned from the data ([datagen/banned.json](datagen/banned.json)).

### 3.4 Shape grid

| Dimension | Values |
|---|---|
| Opener | none / okay / roger / houston |
| Form | question / command / clipped noun phrase / "need X" |
| Where the deciding word sits | early / late / abbreviated |
| Disfluency | none / filler / false start / repeat |
| Length | 1–3 / 4–7 / 8+ words |

- Each request names one cell and one family. The agent returns an **aligned set**: the same sentence for every sibling, plus a report version labelled `unhandled`. The set shares one group id.
- Coverage is tracked per family × cell, and work orders always send the agent to the emptiest cells.

### 3.5 Filters

- **Rule checks:** lowercase; slot verbatim and from the train pool; no dev or test names; exactly one deciding word (no sibling's word); reports contain no request verbs; length matches the cell; no banned examples.
- **Blind relabel, two steps:** `qwen3:8b` reads guide §1–§4 and labels the row without seeing the intended label, with its answer constrained to the 36 labels. If it disagrees, `qwen3:14b` takes a second blind look. The row is kept only if one of them gives the intended label.
  - Each model alone agrees with 93% of the hand-written dev rows, but they make different mistakes: 8B misreads reports and jargon, 14B treats "roger, …" requests as read-backs. Together they keep 98%.
  - Rows both models reject are dropped, never overridden or reviewed.
- **Dedup:** same label, MinHash Jaccard ≥ 0.8 or ruler cosine ≥ 0.9 after removing filler words, against train and dev. Cross-label exact duplicates are rejected.

### 3.6 Hard cases and `unhandled`

- **Which-one pairs:** every aligned set covers all siblings in the same frame (Siri "Errors Live Inside Blocks").
- **Keyword traps and reports:** every aligned set has a report row; extra sets hold chatter, out-of-scope requests, negations, fragments, Whisper-style noise and jargon traps.
- **Jargon:** from `data/suits_glossary.json` and `data/nasa_acronyms_eva.json`.
- **Procedure lines:** MD Appendix A lines, as written, are `unhandled`.
- **Whisper on noise-only clips:** at the shipped settings Whisper returned nothing on 150 noise clips, so noise rows come from the agent's noise set only.

### 3.7 Whisper pass

- macOS `say` with 10 voices at a varied rate; 300–3400 Hz band-pass; pink noise plus fan hum at 5–20 dB SNR; light clipping.
- Half the clips go through Opus ~24 kbps with 0–5% packet loss (WiFi).
- `faster-whisper` `base.en` with the shipped settings.
- Each output keeps its row's label. A misheard deciding word ("scrubber be") is kept; a deleted one, or one that became the sibling's word, is dropped. The slot span comes from word alignment, so misspelled names stay as slots.
- The alignments build the confusion table (`data/gen/asr_confusions.json`). From round 2, the table is also applied to train text, as the doc suggests: only confusions seen 3+ times, never on slot names, never ones that change meaning ("co2" → "o2") or delete a deciding word, and every variant must still pass the deciding-word rules (`datagen/confusion_aug.py`).
- Round-trip and confusion variants together are capped at 75% of a label's base train rows. Whisper-corrupted dev was the weakest score after round 1, so the cap went up from 50%.

### 3.8 Train, evaluate, target

- Each round trains MiniLM (intent and slot heads) and reports on dev and Whisper-corrupted dev: confusion by family, slot F1 on unseen names, and CheckList (§4.7).
- The next round's budget: ~60% on the worst confusion pairs, ~25% on close variants of wrong or barely-right dev rows, ~15% on failing CheckList tests and empty grid cells.
- Round 0 is ~40 rows per intent; later rounds add ~800–1,000 rows.
- **Stop** when the within-label mean cosine is below 0.5 and dev accuracy per family is flat for 2 rounds. Then the frozen test is scored once.

## 4. Data checks

All gates run on every data change. A failing gate blocks training.

**Ruler model:** `sentence-transformers/all-mpnet-base-v2` at revision `e8c3b32edf5434bc2275fc9bab85f82640a19130`. Frozen, never trained. Student: `all-MiniLM-L6-v2` at `1110a243fdf4706b3f48f1d95db1a4f5529b4d41`.

### 4.1 Normalization
- NFKC, lowercase, strip punctuation, collapse spaces. No word rewriting. The same function is used in checks, training and runtime.

### 4.2 Duplicates
- Exact duplicates → drop.
- Lexical near-duplicates: MinHash on word 1–2-grams, LSH at Jaccard 0.7 (datasketch `MinHash.bulk`, `MinHashLSH`, `MinHash.jaccard`).
- Semantic near-duplicates: ruler cosine ≥ 0.92 (sentence-transformers `util.paraphrase_mining`).
- **Check:** none left; later rounds top labels back up.

### 4.3 Leakage
- **Test rows are never compared with train or dev rows.** Comparing them means reading the test, which leaks it into the loop. The test is opened only to score a milestone.
- Leakage is prevented by how data is made instead:
  - The generators and labellers never see test rows.
  - Test slot names are in their own pool; train and dev may not use them (rule check).
  - Round-trip rows stay in their parent's split.
- Dev and train are compared with each other (dedup, §4.2).
- **Check:** no test or dev slot names in train; no code outside `final_eval.py` reads `data/frozen/`.

### 4.4 Diversity gate

| Metric | Gate |
|---|---|
| Within-label mean cosine (all pairs, per split, no round-trips) | ≈ 0.50; warn > 0.55; fail > 0.62; warn < 0.30 |
| Mean over all labels | 0.45–0.55 |
| Within-label max | < 0.92 |
| Test → train nearest neighbour | p95 ≤ 0.85; max < 0.90 |
| Test vs train self-similarity | test median ≤ train median + 0.02 |
| Distinct word bigrams per label | ≥ 0.6 (warn) |

- Thresholds are set once in the pilot, then frozen.

### 4.5 Label errors
- **Two-step blind relabel** on every generated row (§3.5); rows both models reject are dropped, never overridden.
- **Out-of-fold predictions** (5-fold by group) and a **kNN vote** (≥ 4 of 5 ruler neighbours disagree) flag rows already in train for review.
- **Check:** relabel agreement per label is reported each round; a label below 70% means its card or the guide needs fixing.

### 4.6 Balance

| Check | Gate |
|---|---|
| Command labels, train count | within ±10% of the median |
| `unhandled` share of train | 15–25% |
| Round-trip rows per label | ≤ 50% of its other rows |
| One slot name per label | ≤ 15% |
| Test rows per label | 10, frozen |

### 4.7 Behavioural tests (CheckList)
- Runs in `.venv-checklist`. Build with `TestSuite.to_raw_file`, predict in the main env, score with `TestSuite.run_from_file`.
- Bases come from dev rows only. Never train or test rows.

| Test | Type | Expectation |
|---|---|---|
| Keyword traps, callouts, Whisper "thank you" | MFT | `unhandled` |
| Which-one minimal pairs | MFT | both sides right |
| Unqualified requests | MFT | primary / total label |
| Negation, cancel | MFT | `unhandled` (`Perturb.add_negation`) |
| Filler, punctuation, contractions, politeness | INV | label unchanged (`Perturb.punctuation`, `Perturb.contractions`) |
| Whisper confusions, slot name swap | INV | label unchanged |
| Primary↔secondary, A↔B, gas↔liquid, suit↔helmet | DIR | flips to the sibling (`Expect.pairwise`) |

- **Check:** MFT fails ≤ 2% per test; INV flips ≤ 3%; DIR ≥ 97%.

## 5. Model

### 5.1 Architecture
- MiniLM encoder → mean pooling → intent head (36). A B/I/O token head on the same encoder finds slot spans. One forward pass, max 32 tokens (Siri "SUITS Version", slots).

### 5.2 Training
- **A. Floor:** frozen MiniLM + logistic regression.
- **B. Fine-tune:** intent loss + slot loss, 5 seeds, early stop on val macro F1.
- **C. Experiment:** contrastive warm-up (`BatchHardSoftMarginTripletLoss` + `GroupByLabelBatchSampler`). Keep only if the which-one pairs improve by ≥ 0.5 points.

### 5.3 Teachers and distillation
- Fine-tune 3 bigger encoders (e.g. `all-mpnet-base-v2`, a bge-large, an e5-large). Different models make different mistakes (Siri "Why Different Models?").
- Combine them with a geometric mean (Siri "Two Ways to Average").
- Distil into MiniLM: hard-label loss + temperature-softened KL to the teachers, on train data only. This is a small custom loss; `DistillKLDivLoss` is for similarity scores.
- Average the weights of 3–5 student runs (`SentenceTransformer.merge`, "linear"). This adds no latency. Keep it if it isn't worse.
- **Check:** teachers beat the student on val; the distilled student beats plain fine-tuning.

### 5.4 Calibration and reject
- Temperature scaling on val.
- Reject model: a small logistic regression on top-1 probability, top-1 minus top-2 margin, Whisper `avg_logprob`, `no_speech_prob`, and n-best agreement (Siri "More Rejection Signals").
- Set `MIN_CONF` so 98% of real commands pass, and report how much chatter gets through (Siri "Judge at an Operating Point").
- A wake word starts each command (it has worked reliably), so most chatter never reaches the model. `MIN_CONF` covers what gets through after the wake word.
- **Check:** ECE ≤ 0.03 after scaling.

### 5.5 Whisper n-best
- Take the top 3 transcripts from CTranslate2, run MiniLM on all 3 in one batch, and weight by transcript score (Siri "N-Best Lists"). It costs about the same as 1-best.
- Keep it if it gains ≥ 0.5 points on `dev_audio_synth`.

### 5.6 Slot resolver
- Match the span to the catalogue by spelling (rapidfuzz) and sound (Double Metaphone), and keep the top 3 (Siri "Two Different Jobs").
- Clear winner → `match`. Close call → `ask`. `Add_waypoint` with no match → `new`, the name kept verbatim. Other labels with no match → `ask`.

### 5.7 Follow-ups
- A rule outside the model: keep the last fired intent (and its slot) for ~10 s.
- A short follow-up that names only a qualifier ("and secondary?", "what about bravo") maps to the last intent's sibling with that qualifier. The model labels these `unhandled` on their own; the rule runs before the reject step.
- A follow-up that names only a place or task ("and the lander?") keeps the last slot label with the new name.
- Clear the context on timeout, on any other `unhandled` turn, or when the qualifier has no sibling. Stale context never fires a command (Siri "Guardrails").
- **Check:** a scripted follow-up test (pairs and triples of turns, including timeouts) fires 0 wrong commands.

### 5.8 Data engine
- This is the loop's targeting step (§3.8): spend the next round on the worst confusion pairs, close variants of wrong or barely-right dev rows, and failing CheckList tests.
- Mine around real errors, not the most uncertain rows, which are mostly junk (Siri "Why Not Label the Most Uncertain?"). Never mine from test.

### 5.9 Slices
- Report F1 per slice every run: family, round, grid dimension, report rows, Whisper variants, slots, unseen names, hand-written vs generated dev (Siri "Slices").
- **Check:** no slice drops > 2 points without an explanation.

### 5.10 Siri ideas

| Kept | Dropped |
|---|---|
| Teacher ensemble + geometric mean, distilled | Runtime ensembles (latency) |
| Slot tagging + resolver with top 3 | Domain hierarchy (one softmax is enough) |
| Operating point, reject signals, n-best | Wake-word cascade, speaker ID (outside the text model) |
| Data engine around errors, slices | Labelling the most uncertain rows |
| Follow-up rule with guardrails | LLM at runtime (latency, hallucination; MD §2b) |

## 7. Shipping

### 7.1 Export
- `torch.onnx.export(dynamo=True)` for the encoder plus both heads. sentence-transformers' ONNX helpers need `optimum-onnx`, which forces transformers 4.
- **Check:** ONNX matches PyTorch within 1e-4 (tested: 6e-7).

### 7.2 Quantisation
- ONNX Runtime `quantize_dynamic`, int8 (23 MB vs 91 MB).
- **Check:** §6.3 int8 targets; recheck the pairs and calibration.

### 7.3 Latency (MacBook Air M5, CPU)

| Stage | Budget p95 | Measured p50 / p95 |
|---|---|---|
| Whisper `base.en` float32, beam 5, n-best 3 | ≤ 700 ms | 420 / 850 ms |
| *(ref)* Whisper int8, beam 5 | – | 650 / 690–1,080 ms |
| *(ref)* Whisper float32, greedy | – | 330 / 360 ms |
| MiniLM int8, batch 3, 1 thread | ≤ 5 ms | 2.3 / 3.4 ms |
| Our NLP total | ≤ 10 ms | – |
| Link, cable / WiFi | ≤ 30 / ≤ 200 ms | to measure |
| End to end, cable / WiFi | ≤ 750 / ≤ 950 ms | – |
| Cold start | ≤ 2 s | Whisper load 0.6 s |

- float32 Whisper is faster than int8 on Apple CPU. MiniLM is faster on 1 thread.
- Greedy Whisper fits ~400 ms but loses n-best.
- **How:** 50 warm-up and 1,000 timed calls with `time.perf_counter_ns`; report p50 / p95 / p99 per stage. The latency script runs on every export, and a regression > 20% fails it.

### 7.4 HUD–MacBook link
- Send only the speech segment. Cable sends raw 16 kHz PCM; WiFi sends Opus ~24 kbps.
- Each request has an id and a timestamp. The HUD drops results older than 2 s, so **a late result never fires a command**.
- On timeout, the HUD shows "say again" and queues nothing.
- **Check:** link latency within budget; WiFi-codec accuracy within 1 point of raw; a scripted test of delayed, dropped and out-of-order results fires 0 commands.

### 7.5 Package
- ONNX model, tokenizer, normalizer, temperature, `MIN_CONF`, reject model, slot catalogue, labels, model card.
- **Check:** a clean env reproduces the val metrics.
